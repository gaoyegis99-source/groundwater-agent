# Data + Knowledge 设计验收矩阵

| ID | 验收点 | 通过标准 |
|---|---|---|
| D-01 | 现有模型复用 | 每个建议字段映射到现有合同，证明不足后才新增 |
| D-02 | 语义身份 | Profile 精确绑定 dataset/version/semantic/field |
| D-03 | 未知语义 | 未核验字段不升级为事实 |
| D-04 | 单位与基准 | 单位、CRS、垂向基准独立表达，未知不推断 |
| D-05 | 质量分层 | 文件、规则、科研适用性不混成一个 PASS |
| D-06 | 质量证据 | 区分真实执行结果与外部声明 |
| K-01 | 知识分类 | 映射现有 metadata，不重复建服务 |
| K-02 | 来源定位 | 核心方法可追溯来源和 locator；未核实明确标记 |
| K-03 | 内容去重 | Model Card 不重复维护 Manifest 参数和方法理论 |
| K-04 | Demo 隔离 | 正式科研默认检索不混入纯演示知识 |
| K-05 | 版本治理 | 过期/撤回知识默认不作为当前证据 |
| K-06 | 证据读取 | 仅完整读取且核验的 Evidence 可作为依据 |
| I-01 | 数据所有权 | 不复制权威数据，不把通用知识伪装成项目事实 |
| I-02 | 兼容性 | 数据库提案 additive，旧客户端行为明确 |
| I-03 | 范围 | 不涉及 Kernel、Runtime、Planner、Executor、UI |
| I-04 | 可测试性 | 每项设计有正向、负向、版本和隔离测试 |
