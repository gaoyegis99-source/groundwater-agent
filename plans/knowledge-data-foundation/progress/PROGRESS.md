## K03 · 分类与元数据

Knowledge 原生 `KnowledgePackageV1` 已能表达种类、别名、来源、模型三元组、定位、必要上下文和精确 Data 绑定。当前领域资产为旧版 `domain-knowledge.v2`，转换只映射标题、摘要、版本、语言、来源、正文和包摘要。模型身份只在正文，`kind` 走默认 `knowledge`，全部领域 seed 都是通用范围。已有原生服务字段和旧领域包装配路径应分别核对。

建议先用现有字段表达粗类，再在受版本控制的领域资产清单登记细类和用途。Theory 与 Data Dictionary 对应 `definition`，Method 对应 `method`，Standard 对应 `rule` 并保存官方来源及条款定位，Case Study 对应 `case`，Model Card、Operator Card 和 Troubleshooting 保留 `knowledge` 及各自细类。Model Card 使用模型 ID、版本、校验和；Operator Card 保存算子身份及实现依据；Data Dictionary 只有针对实际数据时才带绑定。单独登记演示、一般方法和项目事实。公共 API 的八类可筛选性留到评测证明需求后再判断。领域 seed 需要表达原生字段时，由装配兼容层做显式版本化映射和合同测试。

绑定有一处文档与代码口径差异。检索实现允许整版本绑定覆盖同一版本及语义下的字段请求，README 将 `fieldId=null` 描述为仅匹配整数据绑定。K06 应固定两个请求方向的预期，并验证新语义修订与字段错配。 [匹配实现](../../../source/services/knowledge-next/src/platform_knowledge_next/retrieval.py) · [服务说明](../../../source/services/knowledge-next/README.md)

## D02 · 地下水字段语义缺口

下表为建议的数据字典口径。单位是候选登记口径，具体值和适用范围由实际资料和核验记录提供。旧版本缺失项保留未知。

| 字段概念 | 候选单位 | 必需依据和适用范围 |
| --- | --- | --- |
| 水位高程 | m | 垂向基准、测量点高程来源和有效期，记录井位、井状态和时间。 |
| 地下水埋深 | m | 深度零点、正方向、量测方式，区分井口、地面或其他参考面。 |
| 水头 | m | 水头定义、垂向基准、含水层或开放层段，注明实测或由参考高程与埋深派生。 |
| 降深 | m | 基线水头、符号、抽水工况和对应时间。 |
| 渗透系数 / 水力传导系数 | m/s、m/d | 试验、经验值或率定来源，登记方向、层位、流体条件、代表尺度与适用范围。 |
| 导水系数 | m²/s、m²/d | 试验解释或 K 与有效厚度推导，核对模型假设和层段。 |
| 给水度 | 1、% | 潜水条件、试验或率定依据，核对比例尺度及与储水系数的区别。 |
| 有效孔隙度 | 1、% | 区分总孔隙度与参与运移部分，登记测定或情景来源。 |
| 补给量 | mm/时段、m³/时段、m/d 等 | 标明深度、体积或通量口径，登记面积、时间窗、估算方法与空间支持。 |
| 开采量 | m³/时段、m³/d 等 | 区分体积与流量，标明计量来源、井或井群、统计时间窗及缺报。 |
| 监测井 | 标识，无单位 | 稳定井号、几何和水平 CRS、测量点、井深、筛管、目标层位、有效期。 |
| 含水层 | 标识，无单位 | 层位身份、命名与解释来源、关联井段、空间或高程范围、解释版本。 |

现有字段 `meaning/unit` 与 `crs/verticalDatum/timeRange/timezone/grain/source` 可存首批声明。流场模型已有单位和垂向角色检查，趋势模型已有单位、时间字段和时间范围要求。建议优先验证同名同单位的水头和埋深能否区分，其次验证补给深度与补给体积、给水度与有效孔隙度。对每条判定保留 `dataset/version/semantic/field` 身份及原始出处或程序回执。 [语义模型](../../../source/services/data/src/platform_data_service/models.py) · [现有模型语义校验](../../../source/kernel/src/platform_kernel/agent_runtime/preparation_tool.py)
