# 阶段 8：端到端验收、试点与发布
## LOCAL WORKSPACE ONLY（强制约束）

本任务只针对 Codex 当前打开的**本地工作区代码**。

### 禁止远程连接和远程操作
- 不连接 GitHub、GitLab、Bitbucket 或任何远程代码托管平台。
- 不调用 GitHub/GitLab API、浏览器、远程 MCP/Connector、远程代码搜索或远程文件读取工具。
- 不执行 `git fetch`、`git pull`、`git push`、`git clone`、`gh`、`glab`、远程 PR/Issue 操作或任何会访问远程仓库的命令。
- 不访问仓库配置的 remote URL；不要为了核实代码而联网。
- 不将本地文件上传到远程服务，不创建远程分支、提交或 PR。
- 不通过网络下载依赖、工具、模型、数据或文档。若环境缺少依赖，报告缺失项和离线解决建议。

### 允许的本地操作
- 读取和修改当前工作区内文件。
- 使用本地 `git status`、`git branch --show-current`、`git log`（仅本地已有对象）、`git diff`、`git diff --check`。
- 运行本地已有的测试、格式化、静态检查、构建和装配命令。
- 搜索当前工作区文件；优先使用 `rg`、`find`、本地 IDE 搜索和仓库已有脚本。
- 创建本地文档、测试、迁移文件和报告。

### 离线失败处理
- 若本地仓库不是完整工作树、子模块未初始化、LFS 文件缺失、依赖缓存不存在或测试需要外部服务，停止相关验证并准确报告。
- 不得用远程仓库内容补齐本地文件。
- 不得声称未运行的测试已通过。
- 不得假设当前本地代码等于远程默认分支；一切以当前工作区实际内容为准。

### 本地数据保护
- 开始前检查 `git status --short`，不得覆盖用户未提交改动。
- 不执行 `git clean`、`git reset --hard`、批量删除或破坏性迁移，除非用户明确授权。
- 不擅自切换分支或改写提交历史。
- 默认不创建 Git commit；只有用户明确要求时才提交。
- 所有输出保存在当前工作区指定目录；不上传、不同步。


全局遵循 `00_MASTER_CONTROL_PROMPT.md`。

## 目标

证明 V2 的业务流程、安全边界、Workflow/Operator 质量和用户体验在真实场景中成立。

## 必测业务场景

1. 新用户从首页进入一个已装配的业务能力。
2. 上传监测数据并完成字段/单位/时间/坐标检查。
3. 选择 Workflow Profile，修改参数并确认。
4. 后台执行时离开页面，再恢复 WorkItem。
5. 查看主成果、诊断、图件和精确来源。
6. 将已发布成果复用到新的工作项。
7. 动态 Operator 组合经过 Catalog、Compiler、白名单和 Confirmation。
8. Operator 版本更新触发依赖 Workflow/Profile/Model 的影响检查。
9. Workflow 发布失败与计算失败分别恢复。
10. 多用户、多项目和只读权限隔离。
11. 旧 Session、旧 WorkflowRun 和历史成果兼容读取。

## 测试分层

- Operator：Schema、Unit、Smoke、Integration、Domain Case、Regression。
- Workflow：Compiler、Profile、输入角色、参数、输出合同、执行、发布。
- Kernel：权限、幂等、状态机、确认、恢复、跨会话关联。
- API：OpenAPI、生成客户端、兼容性和错误合同。
- Web：组件、Hook、路由、无障碍、响应式、SSE 恢复。
- E2E：真实用户业务路径。

## 硬性失败项
- 错误数据版本或错误项目；
- 未授权执行；
- 旧确认授权新参数；
- 重复执行/重复发布副作用；
- 未验证 Operator 被默认开放；
- Workflow 输出合同与实际结果不匹配；
- 执行成功被表述为业务已验收；
- 历史结果无法追溯；
- 断线恢复显示错误状态；
- 跨项目资源泄漏。

## 发布分阶段
- Alpha：内部测试和影子关联；
- Beta：少量目标用户，核心业务路径；
- Pilot：真实项目受控试点；
- GA：完成硬性门槛、用户测试和回滚演练后发布。

## 输出
测试报告、缺陷清单、性能基线、用户可用性报告、迁移结果、回滚演练记录和发布决策。
