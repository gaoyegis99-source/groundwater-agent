# 阶段 4：数据工作空间与业务对象关联体验

## 用户目标
用户能在 WorkItem 中理解本次工作使用哪些资料、资料版本和质量如何、关联哪些监测井/区域/含水层，以及哪些资料尚不能用于计算。

## 范围
现有 Data 目录/版本/语义/字段/质量 UI；WorkItem Data/Knowledge/Workflow/Result assets；REGION/WELL/AQUIFER 引用；上传、检查、选择、附加和可用性状态。

## 原则
1. Data 拥有数据与版本权威；WorkItem 只保存经过验证的引用。
2. Knowledge 拥有文档版本和 checksum 权威。
3. 当前 BusinessObjectReference 不是全球唯一主数据身份；不得宣称 externalId 已完成跨数据集解析。
4. 对象引用显示来源数据、字段、业务键和版本。
5. 历史 SemanticRevision 保留原身份，不替换成当前语义。
6. 不可访问引用显示安全状态，不泄露隐藏内容。
7. “已关联资料”与“本次执行输入”必须区分。

## 用户旅程
WorkItem 资料区 → 浏览/上传/选择 → 查看字段、单位、时间范围、CRS、质量和语义 → 选择输入角色 → Kernel 准备校验 → 结构化补充问题 → 重新准备 → Confirmation 冻结精确引用。

## 质量展示
优先使用 Data 现有质量规则和运行结果。展示质量状态、检查时间、缺失/异常、覆盖范围、字段语义、单位、时间范围、空间参考、版本来源及是否被本次计算采用。UNKNOWN 不得显示为 PASS；不得从文件名猜单位或坐标系。

## 测试
精确版本/checksum、旧语义、字段缺失、单位冲突、CRS/垂向基准缺失、撤权、跨项目引用、重复附加、服务不可用、分页和性能。

## 验收
WorkItem 资料区和业务对象区可用、来源可追溯、不新增主数据服务；必要合同扩展有 ADR 和兼容测试。
