# Codex 分阶段执行 Runbook
## LOCAL WORKSPACE ONLY（强制约束）

本任务只针对 Codex 当前打开的**本地工作区代码**。

### 禁止远程连接和远程操作
- 不连接 GitHub、GitLab、Bitbucket 或任何远程代码托管平台。
- 不调用 GitHub/GitLab API、浏览器、远程 MCP/Connector、远程代码搜索或远程文件读取工具。
- 不执行 `git fetch`、`git pull`、`git push`、`git clone`、`gh`、`glab`、远程 PR/Issue 操作或任何会访问远程仓库的命令。
- 不访问仓库配置的 remote URL；不要为了核实代码而联网。
- 不将本地文件上传到远程服务，不创建远程分支、提交或 PR。
- 不通过网络下载依赖、工具、模型、数据或文档。若环境缺少依赖，报告缺失项和离线解决建议。

### 允许的本地操作
- 读取和修改当前工作区内文件。
- 使用本地 `git status`、`git branch --show-current`、`git log`（仅本地已有对象）、`git diff`、`git diff --check`。
- 运行本地已有的测试、格式化、静态检查、构建和装配命令。
- 搜索当前工作区文件；优先使用 `rg`、`find`、本地 IDE 搜索和仓库已有脚本。
- 创建本地文档、测试、迁移文件和报告。

### 离线失败处理
- 若本地仓库不是完整工作树、子模块未初始化、LFS 文件缺失、依赖缓存不存在或测试需要外部服务，停止相关验证并准确报告。
- 不得用远程仓库内容补齐本地文件。
- 不得声称未运行的测试已通过。
- 不得假设当前本地代码等于远程默认分支；一切以当前工作区实际内容为准。

### 本地数据保护
- 开始前检查 `git status --short`，不得覆盖用户未提交改动。
- 不执行 `git clean`、`git reset --hard`、批量删除或破坏性迁移，除非用户明确授权。
- 不擅自切换分支或改写提交历史。
- 默认不创建 Git commit；只有用户明确要求时才提交。
- 所有输出保存在当前工作区指定目录；不上传、不同步。


## 使用方式

1. 将本目录复制到当前本地工作区文档区，例如 `plans/groundwater-agent-v2/prompts/`。整个流程仅操作本地文件。
2. 在已打开的本地工作区 Codex 会话中先粘贴 `00_MASTER_CONTROL_PROMPT.md`。确认 Codex 使用本地工作区，不启用远程仓库连接。
3. 每次只选择一个阶段提示词执行。
4. 阶段完成后先审查 diff、测试和阶段报告。
5. 只有阶段退出条件满足后才开始下一阶段。
6. 对涉及数据库、公开 API、Operator/Workflow 版本、权限和执行边界的变更，必须单独评审。

## 推荐执行命令

每个阶段开始：
```bash
git status --short
git branch --show-current
git log -1 --oneline  # 仅读取本地已有提交
```

Python 项目按仓库规定运行：
```bash
pytest -q <target-tests>
ruff check <changed-python-paths>
```

Web 项目按 `source/web/package.json` 的 scripts 运行实际存在的命令，不要猜测脚本名。

合同/装配/领域检查必须使用仓库现有工具和开发流程文档。先读取 `source/docs/operations/execution-playbook.md`，不要自行拼凑新的构建步骤。

```text
阶段：

运行的测试命令：
测试结果：
未解决问题：
风险：
是否满足退出条件：
下一阶段前置条件：
```

## 停止条件

- 工作区存在用户未提交改动且可能冲突；
- 现有架构事实与设计不符；
- 需要破坏性迁移或改变公开合同；
- 测试环境缺少关键运行时；
- 关键科学语义或业务对象权威来源不清楚；
- 无法安全恢复数据库或执行状态。

## 重要提醒

不要要求 Codex 一次性执行全部阶段。每阶段的验收结果是下一阶段的输入。遇到不确定问题先形成 ADR，不允许模型自行填补架构决策。
