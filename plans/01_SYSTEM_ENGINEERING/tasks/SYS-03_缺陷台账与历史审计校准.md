# SYS-03：缺陷台账与历史审计校准

## 1. 目标
将历史源码审计逐项核实为当前缺陷或关闭项。

## 2. 非目标
- 不重写整个平台，不创建平行服务、状态表或执行运行时。
- 不修改任务卡范围外的模块；发现必须扩大范围时先提交影响分析。
- 不将 NOT_RUN、UNKNOWN 或 SKIP 写成 PASS。

## 3. 源码范围
- 基线标签和 Git 历史中的旧审计、差距矩阵
- 当前源码、产品清单、领域清单和可重复测试结果
- `当前相关源码和测试`
- 本包 `progress/DEFECT_LEDGER.md`

## 4. 前置依赖
SYS-01, SYS-02

## 5. Codex 执行指令
对旧缺口逐条复核。状态使用 CONFIRMED、NOT_REPRODUCED、UNKNOWN、ALREADY_FIXED_VERIFIED。记录本地 HEAD、文件路径、触发条件和测试。不要把历史静态审计直接当当前事实。

## 6. 测试命令
```bash
`git diff --check`; 相关测试；文档检查命令以本地执行手册为准。
```
执行前必须核实本地脚本、参数、package scripts 和 toolchain。命令不可用时先读取项目执行手册，不得猜测替代命令。

## 7. 验收标准
台账中每个缺陷有证据和复现状态；已修复项有验证；未验证项不被关闭。

## 8. 完成回报
- 本地 HEAD 与初始工作区状态；
- 当前问题是否仍存在及复现证据；
- 修改文件和关键实现；
- 测试命令、退出码、passed/failed/skipped；
- 科学验证结果（适用时）；
- NOT_RUN 项和原因；
- 进度表与缺陷台账更新。
