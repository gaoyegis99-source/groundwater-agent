# 整表描述统计草稿

目标是使用两个节点生成可核对的草稿。第一步按用户提供的规则稳定排序，第二步对表中所有数值列输出完整描述统计。规则缺失时由合同检查保留缺项，草稿保持不可执行。

## 统计合同

新增 `statistics.describe_columns@1.0.0`。输入为 CSV、Parquet 或 Arrow IPC 表，输出为一个 `summary` 值。每列记录总行数、有限值数、空值数、非有限值数、最小值、最大值、均值、总体标准差、第一四分位数、中位数和第三四分位数。分位数沿用线性插值。字段名称沿用输入表，逐列记录类型识别依据。没有有限值的已知数值列保留计数，统计量为 null。

已声明的物理数值类型直接使用。排序后的 CSV 派生表可能以字符串保存所有列，草稿可明确选择允许数值字符串识别。识别检查整列，要求存在有限数值，排除带前导零的整数标识符、布尔和混合文本，并保留跳过字段及原因。该规则描述文件表示。字段的业务含义和单位仍以 Data 和项目约定为准。

数值文本识别默认关闭。以合成资料核验时，提供排序规则并由用户明确开启文本识别后，两个节点通过工作流编译。输入格式可以说明为何需要开启识别，执行合同仍按现有参数来源规则校验草稿。

## 实施顺序

1. 在 Operator Pack 增加整表算子和本地回归。用已冻结的 48 行观测表核对排序后的全部 30 个数值列，并用独立计算核对各项指标。覆盖空值、非有限值、布尔、混合文本、补零编码和关闭字符串推断。共享现有统计计算及空值合同。
2. 新增静态注册模块及统一子进程入口，既有算子通过原执行入口处理。Executor 子进程、Smoke 和命令行使用统一入口。Assembler 校验两份静态注册的键无冲突、覆盖清单，并记录注册摘要。旧算子清单、实现源摘要和版本标识逐项核对。算子通过现有目录、实现锁和 Smoke 发布。
3. Groundwater 组合白名单登记新算子，保留 12 节点预算。冻结输入、用户问题和拒绝执行条件沿用原样，为新装配登记两节点草稿的算子与参数合同。旧装配和旧评估回执继续引用原算子。新验收同时核对原 Data 绑定、排序规则缺项、数值字符串配置及唯一 `summary` 输出。
4. 运行原生算子、装配、编译和草稿 HTTP 回归。分开记录合成资料的技术验证、真实模型复测和现场专业验收。

本次涉及 Operator Pack、Assembler、Executor 子进程入口、产品组合配置和本地评测。工作流计算继续使用现有 Executor 和 Workflow Compiler。公开 API 与数据库结构沿用现有合同。

## 草稿合同校验

两次真实模型请求将排序节点的表同时作为中间数据和最终成果，另外一次缺少数值文本识别。工作流结构编译允许合法的多输出图，也允许省略可选参数。这些校验需要保留。草稿交互根据明确的顺序目标、实际节点和本轮已观察到的输入格式核对这两个决定。

1. 在现有 Kernel HTTP 测试中复现三种提交形状。增加明确要求保留中间表、明确关闭识别和非 CSV 来源的通过用例。核对冻结资料版本、排序规则缺项、零执行和零发布。
2. 增加共用的草稿合同校验，覆盖工具预检、提交修正和最终入库。只有已识别的两节点排序统计请求适用。用户明确要求交付排序表时允许对应输出。只有已核对的 CSV 经过当前字符串保留的排序算子时才提示补齐文本识别。保持显式参数来源，禁止代用户开启识别、推定字段含义、补造规则或放宽执行资格。
3. 将可修正的问题一起交给现有的单次提交修正。通过后仍由原工作流编译器检查。若模型重复提交违约草稿，记录诊断和失败。执行模式、Operator 锁、旧工作流和公开 API 不变。
4. 跑工作流草稿回归、全量 Kernel 和隔离 HTTP 回放。真实模型先前结果继续按原回执记录，新的真实请求单独取得额度后再测。

第二轮检查发现评测投影会重命名 `parameterValues` 的用户定义键。保留这些键的原值并用驼峰名称回放，继续逐项检查实际参数。资料发现的可选标签为 null 时按缺省处理，错误的非空类型仍由现行 Schema 拒绝，并返回数组格式的修正说明。
