## ADR-UI-011 · UI-13 同轮候选检查与执行验收

G18 已单独批准并通过验收。Kernel 用现有修订按 AgentRun 聚合准备候选，以目标类型、ID、版本和规范化参数（含精确输入版本 ID）识别候选。较新检查覆盖同一候选，重复 tool call 保留原回执，旧轮迟到写入不覆盖新轮。历史 head 可从现有修订重建。确认边界只补充缺少明确检查的 action 记录；实际审批和执行继续由冻结 action 决定。两种顺序、历史恢复、重放及轮次隔离由 Kernel 测试覆盖，隔离服务已验证空间受阻时单独执行监测趋势。

G06 的成功后成果待同步由客户端读取状态表示。Executor 提交 Data 后才报告成功。服务端发布可观测性可通过授权的 Run→publication 关系补齐，沿用现有提交顺序。

## ADR-UI-012 · 真实 Provider 结构化输出失败定位

状态为待审批。真实 DeepSeek 自动门禁 24 次中 11 次失败，其中 8 次 Kernel 返回 `AGENT_MODEL_OUTPUT_INVALID`，另有澄清跟进、草稿输出与冻结确认参数各 1 次不符合断言。以失败样本为输入，按 provider 响应形状、Kernel 解码、工具结果编译和确认参数归一化逐层定位。保存可公开的形状和失败码即可，避免落地原始凭证。先核定归因，再制定最小变更，并使用冻结测试完成重复验证。

现有报告可定位两条具体差异。草稿样本 `workflow-draft#2` 已完成编译，但图中添加了 `table.sort` 和未绑定的 `sort_rules` 数据输入。确认样本 `execution-success#2` 的差异路径为 `/eventComparison`、`/eventThreshold`、`/seasonFrequency`。八条 `AGENT_MODEL_OUTPUT_INVALID` 的逐轮诊断为空，现有证据不足以判定上游生成、响应解码或 Kernel 校验的具体责任。

## ADR-UI-013 · G06 成果发布的服务端关联

已批准。Executor 已在作业行保存 `publication_id`，通过 Data 取得提交回执并校验成果引用后才写入 `SUCCEEDED`。通过独立的作业发布读取向 Kernel 提供精确关联，沿用 WorkflowRun 的项目、归属和执行目标检查。公开读取仅投影发布 ID 和状态，完整发布记录仍由 Data 控制访问。旧记录缺失时保留未知。现有 `JobStatusV6` 与执行终态规则保持兼容。

场景 13 按批准后的 13a 和 13b 验收。提交前从服务端观测发布阶段。提交后分别核对 Data 终态、浏览器列表未同步及读取失败，按精确结果引用开放下载。跨项目、跨会话所有者和未认证请求由现有访问边界拒绝。
