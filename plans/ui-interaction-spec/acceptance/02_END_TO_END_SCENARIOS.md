# E2E 场景

1. 普通咨询：不创建 Task/Run。
2. 创建持续研究：服务端创建 Task，Session 显示目标。
3. 澄清水位高程/埋深：回答经统一消息入口提交，不等于确认。
4. 上传数据：附件状态、版本身份和质量报告准确。
5. 局部阻塞：缺坐标阻断空间分析，不误阻断可行时序分析。
6. 方法建议/Draft：依据可查看，DAG 折叠，Draft 不可执行。
7. 修改方案：新 revision，旧 Draft 保留，旧 Confirmation 失效。
8. 确认：确认前无 Run，确认后服务端创建 Run。
9. 多节点执行：状态来自持久化事实，刷新恢复，无假百分比。
10. 执行中追加要求：进入后续队列，不修改冻结参数。
11. 停止竞争：区分请求停止与最终取消/完成。
12. 失败恢复：显示成功/失败/未执行节点；新批次需新确认。
13. 成果发布与客户端同步（ADR-UI-013）。
    - 13a Data 发布进行中：按 Run 读取精确发布 ID 和真实 Data 状态，Run 仍为进行中且无下载。
    - 13b Run 成功后客户端尚未同步：Data 已发布。成果列表未请求、正在读取或读取失败时无下载，重新读取并核验精确引用后可下载。
14. 同 Task 多 Run：结果按 run/resource identity 归属。
15. 基于成果新建 Session：精确附加资源，不继承旧授权。
16. 断线刷新：snapshot reconciliation；不确定回执不盲重发。
17. 会话切换：迟到 API/SSE 不污染新会话。
18. 评审归档：criteria 全部满足才显示 Task 完成，归档保留成果。
