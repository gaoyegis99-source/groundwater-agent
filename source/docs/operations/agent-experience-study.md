# Agent 与管理界面体验评估协议

该协议用于评估 Agent 回复和管理界面是否便于项目成员理解与恢复操作。它属于
`agentExperienceStatus`，只提供体验参考，不阻塞数值模型、数据管线或实验归档。

## 参与者与环境

- 至少 5 名将实际承担 Data/Knowledge 管理职责、但未参与本轮界面实现的项目成员；
- 使用受支持的浏览器和统一 Gateway；
- 使用专用测试实例与可删除的测试资产，不接触正式项目数据；
- 主持人只朗读任务目标，不提示按钮、页签、内部 ID 或恢复步骤。

## 五项固定任务

1. 上传 CSV，核对文件/影响并确认形成不可变 Data Version；
2. 找到该版本，预览并提交一次字段语义修订；
3. 对精确版本执行查询，核对结果范围，并在刷新后恢复该查询；
4. 导入带来源的 Knowledge 包，先解释预检差异，再确认导入；
5. 从首页识别一个失败或待确认操作，说明影响并完成恢复或安全地停止。

每位参与者独立完成全部任务。任务成功要求在不接受主持人导航的情况下达到服务端权威终态，
且没有重复发布、错误版本选择、绕过确认或把技术 ID 当作业务名称。放弃、超时、主持人导航、
错误副作用或只能由开发者修复均记为失败。

## 记录与门槛

报告只记录参与者匿名编号、任务、开始/结束时间、成功/失败、求助次数、错误副作用、观察到的
理解障碍和实例/装配摘要，不记录文件正文、查询条件、知识正文或凭据。报告可给出总体和分任务
成功率；重复发布、越权读取、错误版本提交和跳过确认必须单独列出，不得被平均值掩盖。

未实际执行时报告写 `NOT_ASSESSED[agent-experience]`。自动化基线由 Data/Knowledge
本地 build Playwright 套件提供，覆盖引导式发布/导入、语义修订、查询、失败恢复、
跨服务工作队列、键盘/axe、窄屏和 200% 缩放；自动化结果记录在 engineeringStatus，
人工体验结论不进入 benchmark 的 hard gate。
