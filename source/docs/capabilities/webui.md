# 产品中立的会话式 WebUI

WebUI 是 Gateway 托管的通用产品壳。启动时必须先严格解码装配产生的
`/product-ui.json`，并与 `/api/v12/capabilities` 的产品和模型集合核对。品牌、推荐问题、
模型、参数、输出、案例和执行档位文案由产品包拥有；配置缺失、解码失败或身份不一致时关闭业务操作。浏览器只调用公开 API；对话选项、
确认和执行仍由 Kernel 管理，文件与知识由各自服务读取。前端不保存另一套
业务状态，不包含离线模型或直接创建 Job 的入口。

回复采用渐进式展示。首屏只显示简短结论、澄清问题或 Kernel 的权威执行摘要；
未决问题、草稿缺口、确认、结果和确有必要的选项保持可见。补充说明与全局去重
来源统一放入默认关闭的“更多信息”原生折叠区。来源只显示标题和片段号，
点击后使用结构化精确身份打开知识抽屉；页面不再显示原始回复全文副本、裸
Knowledge ID 或 checksum。刷新后折叠区恢复关闭，运行 Activity 也不盖过答案。

交互遵循三层信息层级：第一层是结果、需要用户处理的缺项和下一步；第二层是单行总体
进度，处理详情只在用户主动展开后显示；第三层是诊断数据，仅在 URL 显式带
`?debug=1` 时提供。普通页面不展示模型请求次数、词元预算、路由记录、request ID 或工具
轨迹。空结果只说明“缺什么”和一个最有用的下一步，不用方法复述、搜索过程和防御性
边界填满空状态。整体进度优先于逐请求进度；限制只在会改变当前决定时出现一次。

Data 与 Knowledge 管理页面由统一 Gateway 提供，并按项目角色授权。统一入口提供
`/data/`、条件启用的 `/knowledge/` 及对应同源 API；只有 `admin` 可以进入，普通
用户上传仍通过主 Web。三个 UI 的 JSON operation 都使用合同生成期产生的 Ajv standalone
校验器，非法成功响应统一收敛为 `API_RESPONSE_INVALID`；二进制内容继续使用显式下载边界。
共享 `packages/ui-boundary` 负责 Problem、request ID、`Retry-After`、身份作用域、有界的
内存诊断记录，以及两个前端共同使用的字段画像响应校验。画像计算和版本存储由 Data 负责，
共享包不拥有 React 状态。管理 UI 的诊断面板只显示
operation、HTTP 状态、耗时、稳定错误码和 request ID，不记录响应正文、文件内容、查询参数或凭据。

Operator Web 采用目录优先的任务工作台。Data 按“数据目录 → 查询分析 → 发布数据”分区，
Knowledge 按“知识目录 → 证据检索 → 导入更新”分区；页签切换不销毁尚未提交的表单或已恢复的
操作状态。两个入口共享工作区壳、错误解释、诊断和跨服务操作中心，任务、筛选与选中资源写入
URL。Data 桌面目录以列表和数据内容为主，CSV/Parquet 的可查询版本通过既有 Table Query
直接显示表格并按每页 100 行读取；XLSX/GeoPackage 继续使用既有 Preview 服务。每页读取上限
不代表创建查询时只计算 100 行，服务端 deadline 和回执仍适用。版本、来源、字段画像及语义治理
按需展开，未提交表单保持挂载。主 Web 的数据库详情也读取同一版本保存的画像。全量统计、
按输入顺序保留的有限个非空样例及版本声明的字段单位分别展示。Knowledge 目录以标题、摘要和
来源概览组织，选中后打开正文阅读抽屉，关闭返回原目录与焦点；版本核对、比较和生命周期确认
在阅读上下文内完成。
业务名称、中文状态、来源和复核日期优先展示，内部 ID、
checksum、原始枚举和完整 JSON 保留在可展开的技术详情中。发布、导入、语义修订和生命周期更新
仍保留显式步骤、版本身份与确认，不以视觉简化改变权限或服务端合同。Knowledge 批量治理必须
先显示服务端预检差异，再以当前版本和生命周期修订号原子提交。刷新时若存在作用域匹配的
query、publication 或 import 恢复记录，页面直接回到对应任务并查询服务端状态；创建新批次前先
清除该身份作用域内的旧浏览器恢复指针，不删除服务端审计记录。

系统身份与连接状态合并为可展开的“系统信息”，高级筛选默认收起并显示已应用数量。
跨服务操作中心在首页加载后立即读取 Data/Knowledge 权威活动，不要求先展开。默认只显示一行
摘要，需处理数量、运行中数量和服务读取失败仍可见；展开后显示完成数量、下一步和完整记录。
失败原因保留原操作链接，运行中明确提示不要重复提交。operation ID、稳定错误码、主体和
精确时间继续放在每项的“技术详情”中。Data
时间线同时包含质量运行/告警、实验运行、模型阶段和别名修订，质量趋势优先使用质量控制面结果，
不再只读取文件 descriptor 的旧投影。

主界面延续灰蓝色；管理界面使用暖白底、深灰正文和少量淡蓝选中/焦点样式，减少重复说明。
当前前端迭代面向桌面使用，移动端专项开发不在本轮范围内。成功、警告、错误及禁用状态保持各自含义。
辅助文字至少 12px，表单与操作按钮使用统一尺寸。分析正文区分标题层级，宽表格可以
获得键盘焦点并横向滚动，科学文字完整换行。确认、成果和错误分别提供稳定的操作层级；
成果优先显示业务名称和简短版本，完整版本、语义、对象及 checksum 在“数据身份”中展开。

### 前端排查路径

排查先从页面可见的稳定错误码和 request ID 开始，再按请求 → 状态 → 业务快照的顺序定位：

1. 确认 Product UI、capabilities 的产品/身份一致性；配置错误应保持业务操作禁用。
2. 使用带 `?debug=1` 的主 Web 诊断区核对 operation、HTTP 状态、耗时和 `Retry-After`，用 request ID 对照服务日志；不要根据浏览器正文或猜测重试写操作。
3. 对 SSE 断线检查 `sse.disconnected`、`sse.reconnected` 和 `snapshot.requested/applied`，以服务端快照而不是事件数量判断最终状态。
4. 对上传、导入、查询和发布先查询已保存的 operation/publication/import ID；网络不确定时保留 ID，只有服务端明确失败才重新提交。
5. 若错误只发生在管理 UI，检查 Operator 身份、权限和跨服务 product/project/subject；若两个服务都失败，再检查 Gateway、readiness 和后端依赖。

诊断记录仅用于当前页面的人工排查，刷新后不作为业务事实持久化；完整审计仍以 Kernel、Data 和 Knowledge 的服务端事件为准。

### 自然语言控制确认

完整的批准、拒绝、停止和取消短语可在运行中立即提交，并显示目标明确的二次确认卡。确认前没有副作用；目标或任务修订变化后按钮撤回并显示失效。普通消息在运行中仍进入本地队列，含有相似词的长句不会触发控制。任务卡可显示本轮识别出的创建、修订、继续或评审动作，但该标签不作为业务事实或执行授权。

## 使用

按 [开发流程](../operations/execution-playbook.md) 分别配置真实 Agent、独立 Intent Router、Embedding 和私有密钥目录。
科研实例默认访问 `http://127.0.0.1:28186/`，不得把默认 Gateway 监听器直接暴露到公网。
Gateway 镜像自行构建前端，不需要在部署主机安装 Node，也没有额外常驻容器。
已有部署不要使用相同 instance ID 执行升级；新实例使用独立 ID 和空数据目录。

1. 点击“新建对话”，上传附件或从“数据库”选择已有数据。
2. 输入自然语言需求并发送。所有普通消息统一由服务端自动判断是普通对话还是编排草稿；方法建议和比较属于普通对话。输入区不提供模式覆盖或斜杠命令。
3. 回复确有下一步选择时，会显示一至三个与当前问题相关的意图选项；点击后只发送对应的自然语言 `AUTO` 消息。
4. 继续在原输入框补充信息；点击选项不会清空尚未发送的草稿或附件。
5. 明确要求执行后，核对确认卡片中的真实模型、资源和参数，点击“确认执行”或填写原因拒绝。
6. 在消息中查看真实运行状态和结果，点击文件、知识引用或图片打开详情。

首页模板显示用途说明，点击后只填入草稿并提供撤销；用户继续编辑后不再用旧草稿覆盖新内容。
会话搜索只接受当前查询的结果，重命名和归档在提交期间防止重复操作，并在失败时保留可重试状态。
上传准备和上传窗口属于选择文件时的会话；切换会话会取消准备并关闭原窗口，迟到的结果不会附加到新会话。

“发送”仅在项目连接成功且输入框有文字或附件时启用。正式演示必须打开
Gateway 地址，不能使用没有 API 代理的 Vite 预览端口。局域网 HTTP 不属于
浏览器安全上下文，前端请求 ID 使用 `crypto.getRandomValues` 生成 UUID，
不依赖只在安全上下文提供的 `crypto.randomUUID`。

意图选项和文字回复“好的”都不是执行批准。分析结果用于后续制图时，
下一批需要重新确认。历史卡片保留当时信息，只有服务端当前有效的确认可操作。
浏览器断线或刷新后从持久消息、意图选项和 Workflow 结果恢复；结果不明的普通消息
不会自动重发。上传把 publication ID 按文件 checksum 保存在浏览器；用户重选同一文件时先查询
publication 状态，再继续附加、重试或说明结果不确定，避免盲目产生重复版本。

每轮的进度面板优先展示由持久 Plan、Confirmation 和 WorkflowRun 事实投影的
用户进度。运行轮和成功完成轮默认折叠，失败轮默认展开；标题只展示总体状态、当前阶段与真实耗时，
不在首屏显示内部步骤数。
过程面板固定在本轮助手正文之前，不进入正文中的“更多信息”折叠区。
固定案例把案例命中、同批输入核验、计划、确认、执行、发布和终态投影为稳定步骤；
多项输入核验只显示聚合计数，不逐项复制对象检查记录。完整计划、参数、输入身份、
执行尝试和成果归属只在任务工作台展示，不在会话过程面板重复。
连续模型请求归并为“选择处理路径”“筛选候选证据”“根据证据生成回答”等用户阶段。
工具步骤的说明来自持久化结果事实，例如候选命中数、完整读取且可引用的证据数、
数据未命中或合同修复重试；不展示模型隐藏推理，也不根据固定模板伪造思考内容。
相同数据版本核验合并为一项。模型请求次数、上下文峰值和原始工具轨迹不进入普通进度面板。
展开后可查看全部业务步骤，
刷新或加载早期消息仍可恢复。这里显示公开执行摘要，不显示模型内部推理。
执行进度区分等待执行、模型执行、结果发布和终态；
没有观测到的短暂阶段不补造。耗时标为“任务用时”，包含对应任务的实际等待，
不预测剩余时间。

确认可用性和任务标签统一来自消息快照。任务已完成但文件详情仍未返回时，
显示“正在同步结果文件”；未发布文件不会提供下载入口。只有后端明确记录
前项阻止原因时，才显示“因前项失败未执行”。实时事件主要刷新消息，任务终态
再刷新结果；计时更新不会触发滚屏或重复播报。Session 事件事务提交后通过
进程内广播唤醒 SSE 订阅者，浏览器按 event ID 刷新消息；秒级查询仅作为
断线、重启和外部执行状态的恢复保障。

上传计算实际文件大小和 SHA-256，分块哈希在 Web Worker 中完成。文件名、
真实资源 ID、版本及 checksum 通过 MessageRequest v5 的 `inputReferences` 与正文分离提交，界面默认显示文件名与版本，精确标识在附件详情中查看；Agent 再次读取
数据核验。预览遵循 Data 的格式和大小限制，资料单位和字段含义由用户及
有效数据字典提供。知识正文按原 checksum 读取，STALE 不显示替换后的正文。

## 数据库工作台

侧栏“数据库”打开近全屏三栏工作台：左栏按关键词、标签和格式检索数据集并游标分页；中栏核对不可变版本、语义、字段质量、单位、CRS、限制和血缘；右栏按格式打开内容查看器。窄屏以“目录、详情、预览”逐级切换。附加操作始终提交当前选中的 `dataset_id/version_id/semantic_id/object_id/checksum`，不解析为可变化的数据集头版本。

CSV/Parquet 使用 Data Query 提供分页表格、筛选、排序和图表；XLSX 与 GeoPackage 使用隔离的有界 Preview 操作；JSON、GeoJSON、GeoTIFF/COG 和 PNG 使用各自查看器。PyTorch 权重和未知格式只显示安全元数据与下载。超过浏览器预览上限、结果截断或 CRS 无法转换时，界面明确说明限制，并继续提供元数据和下载。ECharts、OpenLayers 和格式查看器按需加载，不进入普通会话首屏包。

切换数据或版本立即撤下旧详情、预览和附加操作；只有当前请求返回并核对后才恢复操作。
目录、版本详情、版本列表和比较分别显示加载、空结果与失败重试，迟到的分页结果不会写入新筛选。
版本比较默认只读取元数据，打开内容时才请求预览。窄屏详情隐藏后不进入键盘焦点循环。

## 能力、状态与成果复用

能力目录只展示 `/capabilities` 实际装配的模型，并与 Product UI 合并展示用途、适用条件、输入格式、参数、输出和 deadline。`capabilities.services` 同时决定 Data/Knowledge 入口及状态抽屉组件；未装配的服务不会显示为入口或故障。顶栏状态抽屉仅在打开或用户手动重查时请求 `/api/v12/ready`，将 200 和 503 都解码为结构化组件状态，网络失败显示“未知”。

发布成果可以作为当前会话的下一步精确输入，或带着未发送草稿在新会话继续；两种路径都不自动发送或复用旧确认。同 Dataset 版本比较只比较身份、对象、字段和语义差异，不自动读取全量内容。Product UI 推荐查看器只影响初始视图；与资源格式不兼容时回退自动选择。默认显示元数据的 JSON 成果（例如第三方运行凭据）可通过“查看 JSON 内容”按需展开，并可返回元数据；仍遵守 32 MiB 预览上限。切换数据对象时重建查看器，避免在新版本身份下短暂显示上一份内容。

成果选择在当前用户和会话内保留发布时的精确引用，刷新时可在成果列表返回前恢复。打开待发送、
已附加或已冻结的版本时沿用同一引用，即使 Data 已有更新的语义。命名成果按文件格式补充下载扩展名。

知识目录支持服务端搜索和游标分页；查看原文后返回时保留查询、列表位置和入口焦点。
引用定位保持原始知识版本、单元和 checksum，服务端返回同单元的其他内容也不能替代原引用。
读取失败可以原位重试。管理页目录刷新不把明确选中的历史版本替换为当前版本；保存和生命周期
操作期间禁用重复提交，失败保留表单与所选版本。

## 项目身份与上传

`/capabilities` 提供当前登录用户的 display name 和项目角色。`admin` 管理用户、成员与项目资源；
`researcher` 可新建会话、上传和运行工作流；`viewer` 只读取项目共享资源和报告。会话列表只显示
当前 owner，支持服务端搜索、重命名和归档，默认隐藏归档项。

上传界面明确说明资料对项目成员可见。前端在选择文件前读取 Data capabilities 的权威上传上限，
当前默认值为 1 GiB；哈希和 XHR 可取消，取消会调用 publication abort。网络、认证、容量、Provider
和执行错误显示稳定错误码、请求 ID、可复制操作和 `Retry-After`，不显示密钥、端点或原始请求。

生产构建 Playwright 使用 axe 覆盖首页、上传、数据库、确认和结果，在 1440×900、1366×768、
390×844 和 720×450（200% 缩放等效）下拒绝 critical/serious 发现。自动化不能替代受管
Chrome/Edge 上的键盘、焦点、屏幕阅读器和真实办公网络人工 smoke。

## 任务工作台

右侧“任务工作台”按数据、参数、任务和成果四页保存可复核事实。顶部同时显示任务状态和本轮状态；AgentRun 的 `COMPLETE` 只代表本轮结束，不会直接投影为“任务已完成”。没有长期 TaskContext 但回复仍有未决项时显示“需要补充信息”，并给出数据库入口。

数据页分为待发送、已附加和已冻结。已附加引用来自消息历史，已冻结引用只来自 Confirmation/AgentAction；前端读取精确 Data Version 核验身份，读取失败不会删除历史引用。参数页保留原始、用户修订和恢复批次，只有当前待确认修订可编辑。任务页展示 TaskContext 的目标、条件、步骤、缺口、计划、执行尝试和技术用量。成果页合并 TaskContext 与成功 WorkflowRun 的发布结果，跨轮次按版本去重并保留运行归属。

正文只展示紧凑任务更新和立即操作，完整任务卡位于工作台。未固定页签时，新数据、确认、运行和成果会分别切换到对应页；用户固定后仅显式跳转覆盖。四页签支持方向键、Home 和 End。宽度不超过 1050px 时使用带 Escape、焦点约束和滚动锁定的覆盖面板，640px 以下占满屏幕。跳转正文、数据库或输入框时关闭覆盖面板并将焦点交给目标；已有待确认参数继续在工作台编辑。折叠全屏工作台不会遗留全屏布局。

## 按意图编排算子草稿

需要组合算子生成新工作流时，直接用自然语言说明需要“工作流草稿”及期望产物。例如：

- “先对这份表稳定排序，再计算各数值列的描述统计；排序规则文件暂缺，请列出缺项。”
- “对这些井点求凸包，再取凸包内部点，生成工作流草稿。”

Agent 按需查询已安装算子的输入输出和参数契约，重新读取 Data 版本及 Knowledge Evidence 后编排。
聊天卡片展示节点、端口依赖、预期输出、参数来源及缺项，支持查看完整 JSON
和“导出草稿 JSON”。草稿与会话历史一起保留；再生成会创建另一份不可变草稿。

这一路径固定只生成草稿，不安装、不确认执行，也不创建 Job。
导出的 `WorkflowDraftV1` 包含 Workflow v6 声明、绑定与证据，明确标记
`execution_allowed=false`；即使没有缺项也不代表已发布可执行模型。
后端拒绝未知算子、错误端口、环、不可达节点、格式不匹配和非法参数。
目录使用当前装配合同中的已安装算子集，但当前 Workflow v6 不支持其中四个算子的多文件输入；
Agent 可看到对应限制，不能把不支持的连线导出为合法草稿。

自动判断由服务端 Router 根据自然语言和最近会话选择普通对话、编排草稿或澄清。方法建议、方法比较、解释及实际分析请求进入普通对话；只有用户明确要求执行时才会形成计划和确认。完整的状态查询短语由 Kernel 直接返回持久状态、等待原因和成果链接，不调用 Router。“编排草稿”用于组合算子。失败或刷新时，未发送草稿仍按会话保留。

路由期间过程面板显示“正在判断需求”。选项完全来自 Agent 的结构化输出，前端不再使用固定关键词词表。普通回复只在确有下一步选择时显示一至三个选项；澄清回复显示一个问题和二至三个互斥选项。只允许最新已完成回复下的选项操作，点击立即防重复，并把 `message` 原样作为新的 `AUTO` 请求提交，不附带附件、模式、选择引用或执行指令。自动判断和选项都不会批准计算，执行仍需确认卡片。

### 编排提示词

提示词位于 Kernel 的 [build_draft_instructions](../../kernel/src/platform_kernel/agent_runtime/prompts.py)，
由服务端按草稿模式组装。它要求 Agent 依次完成：

1. 明确用户要解决的问题、期望输出和约束。
2. 查询当前资源、数据字典、方法知识和算子目录。
3. 读取每个候选算子的完整端口、参数和输出契约。
4. 核对单位、CRS、规则文件和必要的显式格式转换。
5. 生成节点依赖、参数来源、证据引用及未解决缺项。
6. 通过一次 `submit_reply` 提交结构化草稿；不能形成合法图时说明原因。

提示词不提供预制节点图、场景答案或固定字段绑定。旧草稿可以作为讨论上下文，
但旧引用不能代替当前轮读取；算子默认值也不能代替文件单位或项目事实。
提示词负责引导，工具权限和 Kernel 校验负责约束可接受的提交。

### 编排模拟数据与方法知识

当前 v12 开发候选使用 seed `20260928` 的确定性模拟数据。Data 保存精确 Dataset、Version、
Semantics、Object 和 checksum；Knowledge Next 保存绑定到这些不可变版本的 Evidence。
质量负例单独发布，不进入默认选择或数据绑定知识。固定样本可按需要补充 CSV、Parquet、
XLSX、JSON、GeoJSON、GeoPackage、GeoTIFF/COG、PNG 和 PyTorch 权重，以验证工作台和
工作流，不把模拟结果声明为现实业务事实。

当前 v12 数据准备使用 `python -m scripts.migration.import_yaozhanbao_case` 和 v12 Compose
流程。导入回执记录源 checksum、数据身份、行数、字段、单位、时区、CRS 与限制；相同清单
重放必须返回相同发布回执。

## 前端开发与检查

Web 使用从 Kernel、Data、Knowledge OpenAPI 汇编的公共 v12 合同。合同位于
`products/groundwater/contracts/`，生成类型位于 `web/src/generated/`，不得手工编辑；合同变更运行
`npm --prefix web run contracts:generate`，常规检查运行
`npm --prefix web run contracts:check`。页面专用的展示模型可以留在 `types.ts`，直接对应
HTTP 的 DTO 应引用生成类型；表查询和预览等关键不可信响应还会在渲染前检查必填字段。

### 界面设计

界面使用中性灰白底色、深灰正文与少量蓝色强调色。首页按常用任务提供平面入口，
侧栏、正文、输入区用细线与留白区分；意图选项、结果、草稿和资料目录内部使用
列表与分隔线，减少嵌套卡片。仅待确认内容保留明确边界和主操作。
不使用渐变、厚重阴影、装饰性背景或额外远程字体。

正文采用系统无衬线字体，桌面主要文本 15px，辅助说明通常 12–13px。
统一线性 SVG 图标不参与按钮名称；可点击操作保留中文标签、焦点轮廓和
明确的禁用状态。状态仍以文字解释，颜色只作辅助。

默认页面只保留必要标签和当前状态，移除重复的目录用法、模式解释与卡片
操作说明；输入区只保留附件、自然语言输入和发送按钮。文件格式限制和保存时间可按需展开，模型、工作流、资源及知识的内部 ID/checksum 不进入会话呈现。结果格式与版本
合并至文件所在行，草稿仅在实际存在缺项或待核实事项时显示对应区域。

桌面和 390×844 窄屏都属于设计与验收范围。宽表格局部滚动，
表头可换行并提供完整名称提示；抽屉切换到详情后保留焦点，Escape 可关闭。
科学参数、版本、缺项和明确确认不因视觉简化而隐藏。

## 浏览器验收

首次准备 Chromium（宿主需具备 Playwright 所需系统库；依赖尚未安装时先运行
`npm --prefix web ci`）：

```bash
cd web
npx playwright install chromium
cd ..
```

对已经运行的 v12 开发候选执行当前浏览器套件：

```bash
PLATFORM_BASE_URL=http://127.0.0.1:28186 \
PLATFORM_WEBUI_REPORT=/tmp/groundwater-v12-webui \
npm --prefix web run test:e2e
```

`npm --prefix web run test:e2e` 默认执行同一套 v12 用例，包括浏览器呈现与发送恢复、
真实 v12 数据和知识抽屉、上传、确认执行、下载、拒绝，以及逐题咨询和证据读取。
默认命令执行 4 个文件中的 16 个用例。腰站堡完整案例需要额外准备 19 项精确 Data 输入
和绑定知识，使用独立命令：

```bash
python -m scripts.migration.import_yaozhanbao_case \
  --gateway http://127.0.0.1:28186 \
  --receipt /tmp/yaozhanbao-import-receipt.json
PLATFORM_BASE_URL=http://127.0.0.1:28186 npm --prefix web run test:e2e:yaozhanbao
```

该命令默认读取
`$XDG_DATA_HOME/groundwater-v6/case-assets/yaozhanbao-transfer-case/payload/`；先执行
`python -m scripts.migration.import_yaozhanbao_case --verify-only`。旧工作区载荷必须通过
`--relocate-from` 生成计划并用 `--confirm` 摘要确认，命令不再接受旧绝对路径
`--manifest`。载荷缺失时会明确返回 `CASE_PAYLOAD_NOT_MATERIALIZED`，不会回退扫描工作区。
命令应指向已准备案例数据的隔离候选，会显式确认并执行迁移学习；不能以默认浏览器套件通过
代替此案例通过。生产构建查看器另由 `test:e2e:build` 验证。

仅运行会话浏览器门禁，创建并清理自己的 Compose 项目、容器与数据卷：

```bash
python scripts/checks/check_compose_e2e.py --product groundwater --webui-only --webui-report /tmp/groundwater-webui-report
```

完整 Compose 验收包含原执行回归及浏览器门禁：

```bash
python scripts/checks/check_compose_e2e.py --product groundwater --webui-report /tmp/groundwater-full-webui-report
```

`scripts/checks/check_compose_e2e.py` 通过真实 Data HTTP v3 准备 CSV、Parquet、XLSX、
JSON、模型权重、GeoJSON、GeoPackage、GeoTIFF、COG 和 PNG 最小夹具，通过隔离网络
Knowledge Next HTTP 发布知识，再启动 Playwright 点击页面。仅外部 Provider 和
Embedding 使用确定性替身；Kernel、Data、Knowledge Next、Executor 和 Workers 均为
实际服务，拓扑中不包含 Resource、旧 Knowledge 或 Qdrant。
浏览器门禁覆盖 v12 消息路由、数据库格式预览、真实会话上传、显式确认、执行结果下载、
拒绝执行、问题矩阵以及刷新恢复。完整 Compose 入口在后端、固定 Agent 场景、当前装配模型和
任务协作通过后运行同一套浏览器门禁。
`results.json` 保存结果，失败截图和 trace 位于报告的 `artifacts` 中。
没有重试配置，不将失败后的自动重跑计作首次通过。

实时 Provider 的当前装配模型语义质量和真实 Embedding 检索门禁分别执行；缺配置时
记录 `NOT_RUN`，不能用浏览器固定 Provider 的结果替代。

## 主任务、排队与停止

主任务卡只在有任务时出现，展示目标、条件、等待原因、步骤和成果链接。业务
评审按钮发送明确条件原文的普通消息，不能批准计算。用量为已记录分析用量。
队列可跨刷新恢复，未提交项可编辑、删除和排序；状态不明项保留原请求标识，
停止后续发送。运行中可停止，或将纠正排为后续消息，已经批准的参数不变化。
正式回复之前可展示明确标记的临时正文；断线、失败和刷新撤回，校验成功后替换。
完整语义见[持续协作交互](../architecture/continuous-collaboration-design.md)。
