# 持续协作交互

此处记录已授权实施的行为，协议版本归[协议与持久化](../reference/contracts.md)，
接口归[HTTP API](../capabilities/http-api.md)，测试与实际运行证据归[验收门禁](../operations/acceptance-gates.md)。

## 主任务与持续计划

一会话最多一个主任务，明确交付目标由 Agent 使用 update_task 建立，普通问答不建立。
任务卡显示原目标、必需条件、等待事项、步骤和成果，不使用推测的完成百分比。
用户原文、Agent 解释和建议分别保存；修改要求走统一消息入口，形成不可变修订。
任务步骤保存依赖、缺口和条件链接；当前 AgentPlan 仍只表示本批计算，Executor
独占内部 DAG。能力仍由静态装配提供；方法适用性与事实冲突需本轮查证后说明，
不能用任务持久化替代精确 Data/Knowledge 读取或跨轮缓存正文。

完成条件按各自证据验收，业务可用性仍待用户逐项评审。已完成记录保留；任务
修订重新开启要求核查。原始目标不能被新主目标覆盖，独立目标另开会话。
采用同一 Kernel 数据库以保持任务与会话事务一致，未引入任务微服务或后台无限循环。

## 浏览器消息排队

队列按 Session 保存到 localStorage，包含正文、附件引用、本地 ID、创建时间和
可选纠正目标，刷新后恢复。尚未提交项可以编辑、删除和上移；关闭页面不继续发送。
仅在本轮结束、无待确认动作、连接恢复且无未核实提交时发送队首。
提交时保存 request ID；发送状态不明立即停队，核查历史回执，必要时显式重试同一
request ID。不能生成新请求绕过不确定状态。队列不是服务端已接收消息，不能表示批准。

## 纠正与停止

- 未批准计算前：停止请求持久化并以旧 AgentRun 为目标；旧分析终态化后才提交纠正。
  迟到的正式回复、草稿和暂存任务修订均不能发布。
- 等待确认时：新输入或停止使旧确认失效，已保存批准内容不改写。
- 已批准执行后：纠正排为后续消息；停止通过 Executor 取消接口处理。
  取消与发布竞争以最终 Job/Resource 事实为准，停止请求回执不等于取消成功。
- 请求可幂等重放，控制状态随历史快照恢复。已发布成果保留，执行恢复仍需新确认。

## 临时正文

SDK 流只提取 submit_reply 的 conclusion.text，通过带序号、无重放的独立 SSE
通道发送。每个订阅队列只保留最新片段，正文最长 16000 字符，解析最多读取 64000 字符、嵌套最多 64 层。增量解析跟踪 JSON 层级与字符串转义，不依赖字段顺序；
忽略其他工具和其他路径的 text，等待不完整转义和 Unicode 序列。
客户端标记“生成中 · 尚未核验”，无执行按钮；失败、断线或刷新撤回临时显示。
最终正式回复通过原有 schema 和证据校验后整体替换预览。片段不进入数据库、
历史、摘要、证据或 Trace；可关闭预览以支持无流式能力的 Provider。

## 验证边界

确定性模型证明状态、事务和协议行为，不能证明真实语言理解与方法选择质量。
真实 Provider、知识检索与长任务评测独立计分；缺少完整配置记录 NOT_RUN，
不将本地回归等同于发布通过。新存储仅用于新隔离部署，原部署和数据卷保留回退。
